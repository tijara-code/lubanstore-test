# Architecture

```
                 ┌──────────────── browser ────────────────┐
                 │  storefront (site/*.html + src/web)      │   admin SPA (src/admin, Preact)
                 └───────┬───────────────────────┬─────────┘           │
                         │ /api/* /invoice /resume│ static dist/        │ /api/admin/*
                         ▼                        ▼                     ▼
   Netlify Functions:  api.mts ── Hono app (src/server/app.ts) ── routes/* ── domain/*
                       job-*.mts ── jobs/* (scheduled) ──────────────────────┘    │
                                                                                    ▼
                       services/* (Thawani, Omniful, Meta, Snap, GA4) ── deps.fetch ── the world
                       db/* (Drizzle) ── PostgreSQL (Supabase, schema "store")
```

## Folders

| Path | What it holds |
|---|---|
| `site/` | The storefront's pages (Arabic sources; `site/en/` is generated), the admin page, and `site/public` (images, clips, fonts, robots, sitemap). |
| `src/shared/` | Rules used on both sides of the wire: `pricing/` (the till: `priceOrder`, offer windows, free delivery, duo/trio), `catalogue/` (types, merge of published + code-owned fields), `orders/` (status flow, phone rules, row types), `attribution.ts` (UTM standard), `pixels/` (normalisers, hashing, event catalogue), `kpi.ts`, `admin/` (admin API types), `money.ts`, `time.ts`. No DOM, no Node APIs. |
| `src/web/` | The storefront's page scripts: `core/` (the `LM` API: catalogue, country, money, cart, stock, parked orders, i18n), `product/`, `cart/`, `header/`, `checkout/`, `tracking/` (pixels, first-party beacon, error reports), `entries/` (one per page). |
| `src/admin/` | The admin SPA: `app/` (shell, nav, tabs registry, kit), `data/` (typed API client + query cache), one folder per tab. See `src/admin/README.md`. |
| `src/server/app.ts` | The Hono app: middleware (deps, release header, no-store), error handling, route registration. |
| `src/server/routes/` | HTTP only: parse, validate, call the domain, answer. `storefront`, `orders` (cash till), `payments` (card till, verify, webhook, resume), `tracking` (beacon & relays), `empower` (hook, stock), `admin/*`, `dev` (fake mode only). |
| `src/server/domain/` | The business: `orders`, `intake`, `till`, `order-admin`, `invoice`, `track`, `health`, `catalogue` (load/publish), `stock`, `payments/*`, `empower/*`, `purchase` + `pixels/*`, `analytics/*`, `admin/*` (auth, audit, panel, catalogue editing). Plain functions of `deps`. |
| `src/server/services/` | Clients for the outside services, plus their emulators (`*/fake.ts`) and the fake world (`fakes/world.ts`). |
| `src/server/jobs/` | Scheduled work (`defineJob(name, everyMin, fn)`), recorded in `ops` as `job:<name>`. |
| `src/server/core/` | Infrastructure: `deps` (what a request/job gets), `http` (errors, request helpers), `outbound` (timeouts and deadlines), `log` (masked error log), `ops` (records and once-only claims), `ratelimit`. |
| `src/server/db/` | `schema.ts` (every table, in Postgres schema `store`), `client.ts` (Postgres or PGlite). |
| `db/migrations/` | Generated by drizzle-kit; applied by hand (`npm run db:migrate`). `db/import-from-v1.sql` copies the original store's data. |
| `netlify/functions/` | `api.mts` (every endpoint), `thawani-webhook.mts` (the portal's current URL), `job-*.mts` (schedules). |
| `scripts/` | `build.ts`, `dev.ts`, `make-en.ts`, `seed.ts`, `migrate.ts`, `admin-hash.ts`, `compare-screens.ts`. |
| `tests/` | `unit/`, `server/` (real app + PGlite + fake world), `web/` (happy-dom), `e2e/` (Playwright on the built site), `parity/` (against the original, when present). |

## Request flow: a cash order

1. `checkout` (src/web/checkout) posts `{ order }` to `/api/order` (JSON, same-site).
2. `routes/orders.ts`: same-site check → `parseIntake` (whitelist, caps, refusals 400) →
   rate limit → `priceBasket` (live catalogue → `priceOrder`; refusals 400, faults 503) →
   `readGate` (shelf for capped boxes, before any lock) → one transaction: `gateStock`
   (409 `stock_short`) + `writeOrder` (dedupe by the browser's idempotency key) →
   `reportPurchase` (Meta/Snap/GA4, once per order) → `{ ok, id, omr, ga4 }`.
3. A minute later the `empower-auto` job (if switched on) pushes complete website orders to
   Omniful; the poll and the webhook move them along `prep → ship → done`.

## Request flow: a card order

`/api/pay/session` (same till, order written `pending/unpaid`, Thawani session opened) →
Thawani's page → back to `checkout.html?paid=<id>` → `/api/pay/verify` asks Thawani by
reference (never trusts the redirect) → `settle` (conditional on the order still being
settleable) → Purchase. The webhook does the same server-to-server; whichever lands second
sees the order paid and stops. Unpaid attempts are cancelled by `orders-expire` after 72 h;
`/resume/<id>?k=<key>` links reopen a session or switch to cash on delivery.

## Data

All tables are in the Postgres schema `store` (Supabase's public API only exposes `public`).
`orders` + `order_events` (every status/payment/edit change, who and when), `shipments`
(Empower parcels), `settings` (the catalogue, versioned), `ops` (small records, switches,
caches), `claims` (once-only work), `events` + `event_hours` (analytics, rolled up after 90
days), `logs`, `webhook_events`, `rate_limits`, `crm`, `admin_audit`, `catalogue_changes`.

## Testing without the world

`deps.fetch` is the only way out. In tests and `SERVICES_MODE=fake` it is the fake world,
whose emulators answer as Thawani, Omniful, Meta, Snap and GA4 do (shapes from the original
store's own emulator and the providers' documentation). The database in tests is PGlite —
real Postgres — started from a cached snapshot of the migrated schema.
