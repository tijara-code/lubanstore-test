# storefront-core — notes

The storefront's foundation in the new repo: the pages, styles, static files and fonts, the
build (Vite + the English generator), the dev command, and the core of the page scripts (the
port of `assets/js/store.js`, `i18n-en.js`, `cities.js`). The other page scripts (main, checkout,
cart, header, pixel, stats) are ported next against this core.

## The LM API

Full table (member → module → meaning) and the load-order guarantees are in
`src/web/core/README.md`. Summary: one `LM` object (`self.ts`); each module adds its members;
members call each other through `LM` at call time exactly as store.js did (so `LM.c = …`,
`LM.now = …`, `LM.stockCap = …` overrides propagate, as several original suites rely on).
Members: `cfg c ready source clock geo debug lang L txt root v esc $ money num moneyHTML
moneyMark omrRate omrNum omr price was img imgFor extraImg scentMark lineMark scentArt extraArt
now ship cod codOn freeDeal freeOver setFree setShipsFree setFreeEndsAt countsFree freeSub
offerCycleMs offerAnchor offerEndsAt isBundle offerCfg offerHere offer offerLeftMs offerEnded
offWords bundleSize bundleOnlySize bundleSizeId bundleSellable bundleScents bundleOpen isTier tierN
tierCfg tierSize tierClockShown tierUnstarted tierEndsAt tierLive tierOn tierWas tierId tierCounts
countries listFor sizes scents extras fromPrice setCountry lineOffered blockedLines itemId lineLabel
extraOf readCart stockShown stockLeft stockPending stockHidden stockHiddenSize stockCap lineBoxes
basketBoxes capRoom lineRoom loadStock queueOrder flushOrders` — every `LM.x` used in the original
assets/js (grep'd) is present. Events `lm:country`, `lm:stock` on window.

Shared helpers used (identical semantics, called with `LM.now()`): `offerEndsAt`, `cycleMs`,
`anchorOf`, `offerOf`, `isBundle`, `freeDealOf`, `setFreeEndsAt`, `setShipsFree` (plus the
page's own condition `LM.offer("bundle")` — the set must be priced here), `tiersOf`,
`tiersUnstarted`, `tiersEndsAt`, `tiersLive`, `canonical`, `counts`, `isTier`, `countsFree`.
Kept as the browser's own (the till's differs or has no equivalent): `LM.offer` (needs a
price), `offerHere`, `offerEnded`, `offWords`, `bundleSellable` (looks at the shelf caps),
`lineOffered` (verified equal to "the till does not refuse it" over 10,000+ random cases in
`availability.test.ts`), `tierOn` (needs the large size on sale).

## How the build works

- **Pages.** `site/*.html` are the original source pages with only these edits (made by a
  script, diff-checked): one `<script type="module" src="/src/web/entries/<page>.ts">` where the
  `defer` scripts were (module scripts are deferred too); `style.css` linked with `media="all"`
  and `desktop.css` with its original `media="(min-width: 768px)"` — a link WITH a media
  attribute is emitted by Vite as a hashed asset and left in place, which keeps the original
  cascade (style.css → checkout's inline `<style>` → desktop.css; checked in the build test).
  Without media, Vite would move the CSS to the end of `<head>`. `?v=447` on images/clips →
  `?v=__ASSET_V__`; `<meta name="build" content="__BUILD_ID__">`; pixel ids → placeholders;
  the Google Fonts block → self-hosted (below). The inline head scripts (lang-remember, early,
  co-hold, the Snap/Meta snippets, JSON-LD) are verbatim; `/api/settings` preload kept first.
  Relative image/icon paths are kept as written (Vite leaves references to files under
  `public/` that do not exist next to the page untouched).
- **Placeholders** are filled by a `transformIndexHtml` (`order: "pre"`) plugin from
  `scripts/site-meta.ts`; the same asset hash is defined into the code as `__LM_ASSET_V__` → `LM.v`.
  - `__ASSET_V__`: 10 hex of sha256 over every file (path + bytes) in `site/public/assets/{img,media,fonts}`.
    A photo overwritten in place changes every image URL → returning visitors get it
    (the README's "Replacing a photo" problem) — no manual bump.
  - `__BUILD_ID__`: `LM_BUILD_ID` || `COMMIT_REF` (Netlify) || git short sha || `local`.
  - Pixel ids: **injected at build** from `META_PIXEL_ID` / `SNAP_PIXEL_ID` (validated digits /
    uuid), defaulting to the original's public ids (`1045103308296251`, `854522c6-…`). One
    variable now feeds both the page pixel and the server relay, so they cannot point at
    different datasets.
- **Code.** Content-hashed names (`/assets/<name>-<hash>.js|css`) replace the original's `?v=N`
  (and v407's `assets/v/N/` paths): a page can only ever name the chunks it was built with.
  `rolldownOptions.output.strictExecutionOrder: true` keeps source import order across shared
  chunks (rolldown otherwise hoists shared chunks above an entry's own modules — this broke the
  English words running first). Cost ≈ 1 KB of init wrappers. `modulePreload.polyfill` off.
  `build.target: es2019 / safari13 / chrome80 / firefox78`.
- **Post-processing** (`scripts/build.ts`): HTML comments removed outside script/style (newlines
  kept, as minify.js did); `style-*.css`/`desktop-*.css` minified with esbuild (style.css
  192 KB source → 96 KB, 21.0 KB gzip; the original's comment-trimmed copy was 102 KB / 21.4 KB
  gzip). Core chunk: 30.6 KB / 10.4 KB gzip (the original store.js: 41.7 KB / 12.1 KB); `dist/_headers` = `netlifyHeadersFile()`; then every
  `src|href|srcset|data-src|data-poster|poster` local reference in every page must exist in
  `dist/`, no placeholder / `/src/` path / Google Fonts reference may survive — else the build fails.
- **English pages.** `scripts/make-en.ts` ports make-en.js (same PAGE dictionary, KEEP list,
  comment stripping, `lang/dir`, switch, `../` rewrite, canonical/og). Changes: the fonts swap is
  `fonts.css` → `fonts-en.css` (Cormorant only) and the Arabic face's preload is dropped; the
  English words are `<script type="module" src="/src/web/entries/en.ts">` inserted immediately
  before the home/checkout entry (where i18n-en.js went before store.js; privacy has no core
  and gets none, as before). A missing word throws `No English for: …` and stops the build;
  `npm run make-en -- --check` also reports stale pages.
- **Fonts (self-hosted).** Downloaded `fonts.googleapis.com/css2` (index/checkout/privacy/404:
  IBM Plex Sans Arabic 300–700, Amiri 400/700, Cormorant Garamond 500/600, display=swap;
  English pages: Cormorant only, as make-en.js produced) with a Chrome 130 user agent; all 31
  woff2 files are in `site/public/assets/fonts/` named `<family>-<version>-<google id>.woff2`
  (unique per content, so the immutable cache is safe); `fonts.css` (36 @font-face) and
  `fonts-en.css` (10) are Google's rules verbatim with local URLs — same unicode-ranges, same
  rendering. Loading stays non-blocking (`preload as=style` + `media=print onload` + noscript).
  Preloaded: the IBM Plex Sans Arabic 400 arabic subset and the Cormorant latin face (Arabic
  pages; English pages: Cormorant only), placed right after the `/api/settings` preload.
  `fonts.googleapis.com`/`fonts.gstatic.com` preconnects removed. The CSP in
  `src/server/site-headers.ts` already allows only `'self'` for fonts and styles — no change needed.
- **Dev.** `npm run dev` = make-en, `vite build --watch` into `dist/`, then
  `startServer()` on `PORT` (8888) with `SERVICES_MODE=fake` (it also creates `.data/` for
  PGlite, which the server's PGlite connect does not). The site is served built (hashed files,
  English pages, headers) exactly as shipped; reload after a rebuild (≈0.3 s).

## Decisions and deliberate differences

1. **The bundled fallback catalogue is `data/catalogue.json`, imported into the core** (it is
   byte-identical to the original `data/settings.json`). The original chain was live →
   `fetch(data/settings.json)` → an inline FALLBACK; now live → the imported file. The inline
   FALLBACK differed only in ways that never mattered in production (no duo/trio prices, older
   offer fields) — the original only reached it when settings.json also failed. `LM.source`
   keeps its two labels (`"supabase"`, `"settings.json"`). Lost detail: when `/api/settings`
   times out, the original could still read the server clock off settings.json's Date header;
   now the device clock is used until a response arrives (none does — the call is aborted).
2. **`LM.root` and `LM.v`** are no longer read off store.js's `<script src>` (the bundle lives
   at `/assets/<hash>.js` on every page): `root` is `"../"` on English pages (they are exactly
   the /en/ pages), `""` otherwise; `v` is the build's asset hash.
3. **Privacy and 404 do not load the core** — the originals loaded only stats.js there (no
   catalogue request, no geo). Their entries are empty until the stats port lands.
4. **`window.LM_CITIES`** is installed by `entries/checkout.ts` (cities.js loaded only on the
   checkout). `i18n-en.ts`/`cities.ts` are DOM-free data modules: the server can import them
   for the English city names an Omniful order carries (the original read i18n-en.js by path).
5. **`"مدينة زايد"`** appears once in `LM_EN` (the original had the same key twice with the
   same value; TypeScript refuses a duplicate key). Same resulting object (parity test).
6. **Overrides of `LM.offerCycleMs`/`LM.offerAnchor` no longer change `LM.offerEndsAt`**: the
   window arithmetic is the shared function now. Two original suites replaced
   `LM.offerCycleMs` with a lifted copy of itself to compare page vs till; that comparison is
   now by construction (one implementation). Every other late binding is preserved.
7. **No-module browsers get no page scripts.** The original was ES5 for old in-app browsers;
   ES modules need Safari ≥ 11 / Chrome ≥ 61. The static page (prices excepted) still renders.
8. **The storage stand-in** gained a `length` getter (the original lacked one; harmless).
9. **`LM.c`/`LM.cfg` before `LM.ready`:** members that read prices (`pick`) answer 0 instead of
   throwing when no market is set yet (store.js threw a TypeError).
10. **Build id** is a commit id, not the integer version (the `?v=` scheme it tracked is gone).
11. **Dev pixels:** the built pages carry the real public pixel ids by default (as the
    original's source did); local browsing therefore loads Meta/Snap if the browser can reach
    them. The pixel worker may want a dev switch.

## Visual comparison (scripts/compare-screens.ts)

Run against the reference (`node /home/claude/tools/ref-server.js 4100`) and the new build
served by `src/server/node.ts`:

```
node --import tsx scripts/compare-screens.ts --ref http://localhost:4100 --new http://localhost:8888 --out .tmp/screens [--js]
```

**JavaScript off (the static state: markup, CSS, fonts): 0.000 % differing pixels on all 28
pairs** — `/`, `/checkout.html`, `/privacy.html`, a 404 path, `/en/`, `/en/checkout.html`,
`/en/privacy.html` × 320, 390, 768, 1366 px, identical page heights. (The reference uses
Google's font files, the new site its self-hosted copies: same glyphs.) The tool scrolls each
page to load lazy images before the full-page shot (the first runs flickered on the lazy
harvest image).

With JavaScript ON (frozen clock, before the page scripts are ported — expected to differ
where the scripts draw): privacy and 404 at 0.000 % (no page script draws there); the
checkouts 0.04–0.16 % (the header's delivery strip and basket count, drawn by header.js);
the product pages 44–54 % (main.js draws the sizes, prices, offers and gallery; the page is
~700 px taller in the reference). These are the numbers the next workers should drive to 0.
